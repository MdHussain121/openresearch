### F-01 · INFO · ty false positive — `anyio.to_thread.run_sync` (STILL OPEN)

**ty output (11 identical diagnostics):**
```
error[unresolved-attribute]: Object of type `type[BrokenWorkerInterpreter]` has no attribute `run_sync`
   --> apps\api\app\api\v1\endpoints\citations.py:209:11
   --> apps\api\app\api\v1\endpoints\citations.py:247:18
   --> apps\api\app\api\v1\endpoints\collaboration.py:354:35
   --> apps\api\app\api\v1\endpoints\graphs.py:46:11
   --> apps\api\app\api\v1\endpoints\papers.py:91:11
   --> apps\api\app\api\v1\endpoints\papers.py:103:22
   --> apps\api\app\api\v1\endpoints\papers.py:144:15
   --> apps\api\app\api\v1\endpoints\papers.py:205:18
   --> apps\api\app\services\ai_writing_service.py:187:30
   --> apps\api\app\services\pdf_extractor.py:138:28
   --> apps\api\app\services\pdf_extractor.py:151:28
```

**Root cause (re-verified):** `apps/api/.venv/Lib/site-packages/anyio/__init__.py:103` declares PEP-562 shim:
```python
def __getattr__(attr: str) -> type[BrokenWorkerInterpreter]:
```
ty applies this return annotation when resolving *any* attribute it cannot otherwise find on the `anyio` package — including submodule access like `anyio.to_thread`. The resolved type collapses to `type[BrokenWorkerInterpreter]`, which has no `run_sync`. Runtime is unaffected: `anyio/to_thread.py` defines `run_sync` normally.

**Status change:** Count increased from 7 → 11 (new call sites in `graphs.py`, additional in `papers.py`, `pdf_extractor.py`). No code fix applied; remains a pure upstream ty issue.

**Remediation:** Track upstream fix; suppress locally with rule-scoped ignores if adopting ty in CI:
```python
# ty: ignore[unresolved-attribute]
await anyio.to_thread.run_sync(...)
```
