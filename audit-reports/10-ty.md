|---|---|---|
| CRITICAL | 0 | No memory-unsafety-class or remotely-exploitable type failures found |

**Headline:** The codebase is *formally* well-typed at declaration level (every ORM column uses `Mapped[]`, only one `# type: ignore` and one `cast()` exist in 77 files, mypy passes). The real soundness risk is concentrated in one systemic pattern: **runtime JSON data (DB JSON columns, user-posted CSL JSON, external-provider responses, the on-disk provider store) is funneled into code that trusts declared shapes without runtime validation**, which no static checker — ty or mypy — can see through `Dict[str, Any]`.

### F-01 · INFO (ty false positive — root-caused) · 7 diagnostics on `anyio.to_thread.run_sync`

**ty output (all 7 identical shape):**

```
error[unresolved-attribute]: Object of type `type[BrokenWorkerInterpreter]` has no attribute `run_sync`
 --> apps\api\app\api\v1\endpoints\citations.py:269:11
269 |     await anyio.to_thread.run_sync(_verify_and_resolve_target)
```

Affected sites (7):
- `apps/api/app/api/v1/endpoints/citations.py:269`
- `apps/api/app/api/v1/endpoints/citations.py:307`
- `apps/api/app/api/v1/endpoints/collaboration.py:321`
- `apps/api/app/api/v1/endpoints/papers.py:86`
- `apps/api/app/api/v1/endpoints/papers.py:190`
- `apps/api/app/services/ai_writing_service.py:172`
- `apps/api/app/services/pdf_extractor.py:134`

**Root cause (verified against installed package):** `apps/api/.venv/Lib/site-packages/anyio/__init__.py:103` declares the PEP-562 deprecation shim

```python
def __getattr__(attr: str) -> type[BrokenWorkerInterpreter]:
```

ty applies this `__getattr__` return annotation when resolving *any* attribute it cannot otherwise find on the `anyio` package — including submodule attribute access like `anyio.to_thread`. The resolved type collapses to `type[BrokenWorkerInterpreter]`, which indeed has no `run_sync`. Runtime is unaffected: `anyio/to_thread.py` defines `run_sync` normally (verified by introspection).

**Runtime failure scenario:** none. Every call site works today.
**Fix:** upstream (ty should special-case module `__getattr__` for submodules) or locally pin/suppress with rule-scoped `# ty: ignore[unresolved-attribute]` until fixed. Do **not** change working code for this.

### F-02 · HIGH · Unguarded chained subscript/get over client-supplied JSON — deterministic 500

**File:** `apps/api/app/services/zotero_service.py:107` (and 79–99)

```python
107:  date_str = str(data.get("date") or data.get("issued", {}).get("date-parts", [[""]])[0][0] or "")
...
80:   data = item.get("data", item)          # item assumed dict
86:   for c in creators:                      # creators assumed List[Dict]
87:       if "lastName" in c or "familyName" in c:
...
90:                       "familyName": c.get("lastName") or ...
```

The import endpoint accepts raw CSL JSON directly from any authenticated caller:

```python
# endpoints/zotero.py:35-47
@router.post("/projects/{project_id}/zotero/import", ...)
def import_zotero_endpoint(..., request: ZoteroImportRequest, ...):
    ...
    return zotero_service.import_csl_or_api_data(db=db, project_id=project_id, request=request)
```

with `ZoteroImportRequest.csl_json_content: Optional[str]` (`schemas/models.py:708-712`). Nothing in `import_csl_or_api_data` wraps per-item processing in try/except (the outer function only guards JSON parse and HTTP fetch).

**Concrete runtime-failure scenarios (all reachable with one crafted POST):**
1. Item = `{"issued": null}` → `None.get(...)` → `AttributeError` → 500.
2. Item = `{"issued": {"date-parts": [[]]}}` → `[0][0]` → `IndexError` → 500.
3. Items array containing scalars: `[42]` → `item.get` → `AttributeError` → 500.
4. Creator as plain string `"Smith"` → `"name" in "Smith"` substring test can match (e.g. creator `"username"`), then `c.get(...)` → `AttributeError` → 500.
5. `creators` present as dict instead of list → iterating yields keys (str) → same crash class.

Because the exception escapes before `db.commit()`, partial adds roll back — no corruption, but every request fails until the payload changes, and the global error envelope masks the cause behind `INTERNAL_SERVER_ERROR`.

**Fix:** validate shapes at entry (`isinstance(item, dict)`, `isinstance(creators, list)`, safe year extraction helper returning `Optional[int]`), or wrap each item in try/except counting `skipped_count` — the response schema already has a `skipped_count` field designed for exactly this.

### F-03 · HIGH · JWT payload `Any` escapes its narrow exception handler

**File:** `apps/api/app/services/auth.py:116-127`

```python
116:  if auth and auth.credentials:
117:      try:
118:          payload = decode_token(auth.credentials, expected_type="access")
119:          user_id = payload.get("sub")        # Any
120:          email = payload.get("email")        # Any
121:          if user_id is not None:
122:              token_data = TokenData(user_id=user_id, email=email)   # pydantic validation of Any
...
126:      except jwt.InvalidTokenError:
127:          pass
```

`decode_token` returns `dict` (i.e. `Dict[Any, Any]`), so `user_id`/`email` are `Any`. If a signed token ever carries a non-str `sub`/`email` (malformed issuer integration, future token-vending code, or a compromised/misconfigured sibling service sharing `SECRET_KEY`), `TokenData(user_id=dict(...))` raises `pydantic.ValidationError`, which **is not** a subclass of `jwt.InvalidTokenError` → unhandled → 500 on *every* request carrying that token, instead of the intended graceful fall-through to the local user at line 129. The same pattern exists in `endpoints/auth.py:100-106` (`refresh_tokens` catches broadly there, so it is safe) and `collaboration.py:200-207` (also catches `Exception`, safe).

**Why not CRITICAL:** tokens are minted only by `_create_token` with `str` values today; exploitation requires a signing-key holder. It remains HIGH because the handler contract ("bad token → local-user fallback") silently breaks for one whole error family.

**Fix:** catch `(jwt.InvalidTokenError, ValidationError)` — or better, validate at the boundary: `if isinstance(user_id, str) and isinstance(email, str)` before constructing `TokenData`.

### F-04 · MEDIUM · JSON-column shape trust across the retrieval/graph/export pipeline

Declared types vs DB reality — all of these columns are `sqlalchemy.JSON`, whose actual content is whatever was inserted (SQLAlchemy does not enforce the `Mapped[]` parameterization):

```python
# models/paper.py:32
metadata_json: Mapped[Optional[Dict[str, Any]]] = mapped_column(JSON, nullable=True)
# models/chunk.py:30-31
embedding:      Mapped[Optional[List[float]]]     = mapped_column(JSON, nullable=True)
metadata_json:  Mapped[Optional[Dict[str, Any]]]  = mapped_column(JSON, nullable=True)
```

Downstream consumers index/`.get()` these without re-validation:

- `apps/api/app/services/rag_service.py:303-306`
  ```python
  meta = paper.metadata_json or {}
  sections  = meta.get("sections", [])
  tables    = meta.get("tables", [])
  equations = meta.get("equations", [])
  ```
  then `_chunk_sections` line 137 calls `sec.get("title")` per element. If `metadata_json["sections"]` is a dict or string (e.g. legacy row, hand-edited DB, another writer), iteration yields non-dicts → `AttributeError` → upload/index endpoint 500s *after* the paper row is committed (paper saved, indexing broken, status stuck).
- `apps/api/app/services/rag_service.py:109-111` — same pattern for `abstract`.
- `apps/api/app/services/graph_service.py:124-127`
  ```python
  refs = meta.get("references", [])
  for ref in refs:
      ref_title = (ref.get("title") or "")...
  ```
  A `references` value that is a list of strings crashes `/projects/{id}/research-graph`.
- `apps/api/app/services/citations.py:83-93` (`serialize_paper_to_bibtex`) and `app/services/export/csl_formatter.py:39-43` — `meta.get("journal")` results are f-stringed directly; a scalar/list value produces corrupted `.bib`/bibliography output rather than a crash (silent data-quality bug).
- `apps/api/app/services/rag_service.py:383-384` — `row.embedding` fed to `cosine_similarity`, which *does* guard `len(v1) != len(v2)` and emptiness — correctly defensive, worth noting as the model to copy.

**Runtime scenario:** any writer that stores the wrong JSON shape permanently breaks chunking/graphs/bibtex for that paper; recovery requires DB surgery. Probability is low while the only writers are internal, but the system already has three independent writers of `metadata_json` (`papers.py:175` full extraction dict, `citations.py:291-299` identifier metadata, `zotero_service.py:137-146`, bibtex import `citations.py:390-400`) — divergent shapes are plausible.

**Fix:** small normalizers (`_as_dict(value)`, `_as_list_of_dicts(value)`) applied where JSON columns are consumed, mirroring the `cosine_similarity` defensive style.

### F-05 · MEDIUM · Corruptible on-disk provider store → persistent 500 loop on AI endpoints

**File:** `apps/api/app/services/provider_settings.py:114-133`

```python
def _load_store() -> Dict[str, Any]:
    ...
    data = json.loads(path.read_text(encoding="utf-8"))
    ...
    if not isinstance(data, dict):
        return {...defaults...}
    data.setdefault("providers", {})
    data.setdefault("active", None)
    data.setdefault("rate_limit_rpm", None)
    return data
```

Top level is guarded, but nested shapes are trusted everywhere downstream: `store["providers"].get(provider)` (lines 178, 187, 194, 204, 230, 255) assumes `providers` is a dict. A `provider_keys.json` containing `{"providers": []}` (one wrong edit, partial write, or sync-tool merge — note this file lives under `storage/` next to user data) makes **every** call to `list_provider_configs`, `get_active_provider_name`, `get_provider_credentials`, `set_provider_config`, `delete_provider_config` raise `AttributeError`. Because `llm_service.generate()` → `provider_settings.get_active_provider_name()` runs on chat/edit/autocomplete paths, the entire AI surface returns 500 until the file is manually repaired — and `_save_store` will happily rewrite the bad shape forever.

**Fix:** after load, coerce: `if not isinstance(data.get("providers"), dict): data["providers"] = {}` (same for `active: str|None`, `rate_limit_rpm: int|None`, `autocomplete: dict`).

### F-06 · MEDIUM · Implicit-Any plugin boundary: untyped return flows into API response

**Files:** `apps/api/app/services/plugin_runtime.py:51-66, 100-104`; `apps/api/app/services/plugin_service.py:186-192`

```python
51:  def resolve_entrypoint(spec: str):          # no return annotation -> Any
...
100:             output = func(result, dict(plugin.config_json or {}))
101:             if not isinstance(output, dict):
102:                 raise PluginEntrypointError("Hook must return a dict payload")
...
# plugin_service.py
186:  def execute_hook_detailed(...) -> tuple:    # bare tuple: element types erased
```

`resolve_entrypoint`'s return is `Any`; the single `isinstance(output, dict)` check verifies *container* type but nothing about values. That unchecked dict becomes `PluginHookExecuteResponse.payload`/`executions` (`schemas/models.py:987-995` declares `Dict[str, Any]`, so pydantic serializes whatever a plugin returned). A plugin returning deeply-nested or non-JSON-serializable values converts to a 500 inside FastAPI's encoder, attributed to core API rather than the plugin. `execute_hook_detailed() -> tuple` additionally erases the `(result, executions)` contract for all checkers — ty included — so a future swap of return order compiles silently.

**Fix:** annotate `def resolve_entrypoint(spec: str) -> Callable[..., Dict[str, Any]]:` and `-> Tuple[Dict[str, Any], List[Dict[str, Any]]]`.

### F-07 · MEDIUM · Untyped `**kwargs` fan-out and unannotated parameters in literature search

**File:** `apps/api/app/services/literature_search_service.py:97-106, 156-158, 249-251, 359-361, 460-462`

```python
97:   async def _dispatch(self, provider_key: str, **kwargs: Any) -> Dict[str, Any]:
...
151:  async def search_openalex(self, query: str, limit: int = 10, offset: int = 0,
156:                            year_start=None,      # implicit Any
157:                            year_end=None,        # implicit Any
158:                            open_access_only=False) -> Dict[str, Any]:
```

Four public provider methods take implicitly-Any `year_start/year_end/open_access_only`. They are interpolated straight into query filters (`f"from_publication_date:{year_start}-01-01"`, arXiv `submittedDate:[{year_start}01010000 TO ...]`). Today the only caller (`endpoints/research.py:51-59`) passes `Query(ge=1000, le=2100)` ints, so behavior is correct — but the moment any other caller (CLI, scheduled job, tests) passes `"2020"` or `None`-adjacent junk, filters degrade silently (empty results, no error). This is precisely the "untyped def crossing a call boundary" class that `check_untyped_defs` cannot catch because the *callee signature itself* is unannotated.

**Fix:** add `year_start: Optional[int] = None, year_end: Optional[int] = None, open_access_only: bool = False` to all four methods (and prefer explicit keyword params over `**kwargs` in `_dispatch`).

### F-08 · MEDIUM · Bare `tuple` returns defeat arity/type checking at unpack sites

**File:** `apps/api/app/services/tabby_setup_service.py:146-149, 161-164, 203, 274`

```python
146:  def endpoint_host_port(base_url: str) -> tuple:
...
161:  def _effective_endpoint() -> tuple:
163:      base_url = ac.get("base_url") or settings.TABBY_BASE_URL or ""
164:      return base_url, *endpoint_host_port(base_url)     # star-unpack: opaque arity
...
203:      _base_url, host, port = _effective_endpoint()      # 3-way unpack of Any
...
274:      base_url, host, port = _effective_endpoint()
```

Both functions return bare `tuple` (element types and length invisible to ty/mypy/pyright alike). The star-unpack makes the arity depend on `endpoint_host_port`'s internals. If either helper's return shape changes (e.g. IPv6 handling adding a zone), the 3-way unpacks fail at runtime with `ValueError: not enough values to unpack` inside the Tabby setup flow — and no checker would flag it today.

**Fix:** `def endpoint_host_port(base_url: str) -> Tuple[str, int]:` and `def _effective_endpoint() -> Tuple[str, str, int]:`.

### F-09 · MEDIUM (latent) · `dict.get(key, default)` vs explicit null — future AttributeError in all export styles

**File:** `apps/api/app/core/text_utils.py:88-99` (reached from `export/csl_formatter.py:36` for all 26 styles, docx/pdf/markdown exporters)

```python
95:           fam = a.get("familyName", "").strip()
96:           given = a.get("givenName", "").strip()
...
99:           initial = given[0].upper() + "."
```

`a.get("familyName", "")` returns the default only when the key is **absent** — an explicit JSON `null` returns `None`, and `None.strip()` raises `AttributeError`. Contrast with lines 42/64 in the same file, which correctly use `a.get("familyName") or ...`.

I traced every current author-dict producer to assess reachability: `identifier_resolver.py:94-99/199/263`, `literature_search_service.py:_split_author_name`, `zotero_service.py:88-100`, bibtex import `citations.py:362-371` — all either always set a truthy `literal` (which short-circuits `format_single` at line 93) or use absent-key semantics. **So the crash is not reachable through current producers** — but the invariant "every author dict has literal or non-null names" is enforced nowhere. One new producer writing `{"familyName": "X", "givenName": null}` breaks every DOCX/PDF/Markdown bibliography export for papers using those authors.

**Fix:** change both lines to `or ""` style: `fam = (a.get("familyName") or "").strip()`.

### F-10 · MEDIUM · Module-level aliasing of optional dependency misleads every checker

**File:** `apps/api/app/services/provider_cache_service.py:16-19, 55-58`

```python
16:  try:
17:      import redis
18:  except ImportError:
19:      redis = None  # type: ignore[assignment]
...
55:  if redis and settings.REDIS_URL:
56:      try:
57:          client = redis.Redis.from_url(...)
```

After suppression, `redis` is inferred `None`-typed by mypy and by ty; the `redis.Redis` access survives only because the tools treat the name loosely in different ways (mypy via the blanket ignore + loose module handling; ty because `redis` resolves as an unresolved-import `Any` when the package stub isn't picked up). Under stricter settings both flag the follow-on accesses as unreachable/None-attribute. The same `Optional[Any]` softening appears at `collaboration.py:77` (`redis_client: Optional[Any]`) and `provider_cache_service.py:36` (`_redis_client: Optional[Any]`), erasing all Redis API checking.

**Runtime risk:** low today; maintenance trap tomorrow (renames of `Redis.from_url` won't be caught anywhere).

**Fix:** keep the capability boolean separate from the module object:
```python
REDIS_AVAILABLE = importlib.util.find_spec("redis") is not None
if REDIS_AVAILABLE:
    import redis
```
then annotate clients as `Optional["redis.Redis"]` under `TYPE_CHECKING`.

### F-12 · LOW · Dead falsy-guards on non-Optional ORM fields (type-lie smell)

```python
# api/v1/endpoints/documents.py:123
123:  document.version = (document.version or 1) + 1     # version: Mapped[int], non-nullable
# services/collaboration.py:52-53
52:   if hasattr(document, "version") and getattr(document, "version", None) is not None:
53:       document.version = int(document.version) + 1
# api/v1/endpoints/comments.py:35
35:   replies_resp = [_build_comment_response(r) for r in (c.replies or [])]   # replies: Mapped[List[...]]
```

`document.version` is `Mapped[int]` with `nullable=False` (`models/document.py:27`), so `or 1`, `hasattr`, and `int()` are dead code that tells readers (and checkers' narrowing) a falsehood about the invariant. Harmless at runtime; costs strictness elsewhere (a genuinely-Optional case nearby will look "already handled").

**Fix:** delete the guards (`document.version += 1`), or if version-defaulting is truly needed, do it at flush default level.
